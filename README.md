# FraudGuard AI

## Project Overview

Financial transaction fraud is a multi-billion dollar problem globally. As digital payments scale, fraudsters deploy increasingly sophisticated tactics to bypass static rule-based systems. Traditional threshold-based engines struggle to adapt to new attack vectors and often block legitimate transactions, severely degrading the customer experience.

**FraudGuard AI** is a decision-support prototype built to detect anomalous and fraudulent financial transactions in real-time. By utilizing a hybrid machine learning pipeline encompassing supervised classification and unsupervised anomaly detection, the platform assigns dynamic risk scores to live transactions, providing human analysts with actionable, explainable intelligence.

## Key Features

- **AI fraud detection**: Multi-model intelligence scoring transactions simultaneously.
- **XGBoost**: Supervised tree-boosting algorithm trained on historical fraud patterns.
- **Isolation Forest**: Unsupervised model detecting non-linear structural outliers.
- **Autoencoder**: Unsupervised neural network capturing hidden dimensional anomalies.
- **Hybrid Risk Engine**: A weighted consensus engine (60% XGBoost, 20% Isolation Forest, 20% Autoencoder) that determines the final risk score.
- **SHAP Explainability**: Translates complex ML math into human-readable driving factors (e.g., "Device Type increases risk").
- **Real-time analysis**: Sub-second end-to-end inference pipeline.
- **Fraud alerts**: Automatic generation of High/Critical severity alerts for manual review.
- **Analytics**: Macro-level visibility into platform volume and fraud trends.
- **Investigation dashboard**: Interactive UI for analysts to inspect SHAP factors and behavioral history.

## Architecture

FraudGuard AI utilizes a robust, decoupled architecture:

```
Frontend (React + Vite + TailwindCSS)
        ↓  REST API (JSON)
FastAPI (Python Backend)
        ↓  Pandas DataFrame mapping
ML Pipeline (Scikit-Learn + XGBoost + SHAP)
        ↓  SQLAlchemy ORM
Database (SQLite / PostgreSQL)
```

## Machine Learning

The platform utilizes a multi-layered Hybrid Risk Engine to maximize recall while minimizing false positives:

1. **XGBoost (Supervised)**: The primary classifier. It learns explicitly from labeled historical data to recognize known fraud signatures.
2. **Isolation Forest (Unsupervised)**: Trained exclusively on legitimate transactions, it builds distance-like partitioning trees to isolate structural outliers that deviate from normal behavior.
3. **Autoencoder (Unsupervised)**: A bottleneck neural network (76-32-16-32-76). Fraudulent transactions, having patterns not seen during training on legitimate data, incur a high Mean Squared Error (MSE) reconstruction loss.

## Dataset

The models were trained on the **IEEE-CIS Fraud Detection dataset**.
*Note: Due to size constraints and data privacy best practices, the raw `*.csv` dataset files are strictly ignored by Git and are not included in this repository.*

## Features

The pipeline engineered and selected 76 critical features from the original 394 available in the IEEE-CIS dataset. Important engineered feature domains include:
- **Transaction Context**: Transaction Amount (`TransactionAmt`), Product Code (`ProductCD`).
- **Velocity Metrics**: Time since last transaction, transaction frequency within 24h windows (`C1`, `D1`).
- **Device & Identity**: Device Type (`DeviceType`), IP masking flags, and email domain behavioral mapping.
- **Vesta Engineered Variables**: Obfuscated engineered features capturing complex network behaviors (e.g., V-features).

## Evaluation

The models were evaluated against an unseen holdout set. The following are the *actual* metrics generated by the trained models:

**Dataset Split Statistics**
- Total Transactions: 590,540
- Fraud Cases: 20,663 (3.5%)
- Legitimate Cases: 569,877

**XGBoost Metrics**
- **Precision**: 22.77%
- **Recall**: 70.49%
- **F1 Score**: 34.42%
- **ROC AUC**: 90.09%
- **PR AUC**: 47.39%

**Isolation Forest Metrics**
- Average Legitimate Score: 18.65
- Average Fraudulent Score: 32.68

**Autoencoder Metrics**
- Average Legitimate Reconstruction Error: 0.72
- Average Fraudulent Reconstruction Error: 1.99

## Installation

Follow these steps to run the platform locally:

### 1. Create environment
Ensure you have Python 3.9+ installed.
```bash
python -m venv .venv
source .venv/bin/activate  # On Windows: .\.venv\Scripts\activate
```

### 2. Install dependencies
Install backend requirements:
```bash
pip install -r backend/requirements.txt
```

Install frontend requirements:
```bash
cd frontend
npm install
cd ..
```

### 3. Configure environment variables
Create a `.env` file in the `backend/` directory:
```env
DATABASE_URL=sqlite:///./fraudguard.db
API_KEY=your_secure_api_key_here
ALLOWED_ORIGINS=["http://localhost:5173", "http://127.0.0.1:5173"]
```

### 4. Start backend
```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

### 5. Start frontend
Open a new terminal window:
```bash
cd frontend
npm run dev
```
Navigate to `http://localhost:5173`.

## API

### `GET /api/health`
Validates the backend connectivity and model memory status.
**Response**:
```json
{
  "status": "healthy",
  "service": "FraudGuard AI",
  "version": "1.0.0",
  "models": {
    "xgboost": true,
    "isolation_forest": true,
    "autoencoder": true,
    "explainer": true
  }
}
```

### `POST /api/fraud/predict`
Accepts a transaction, maps it to ML features, and evaluates it using the Hybrid Risk Engine.
**Request Headers**:
- `X-API-Key: your_secure_api_key_here`

**Request Body**:
```json
{
  "transaction_id": "TX-12345",
  "user_id": "USER-99",
  "amount": 250.00,
  "transaction_type": "Purchase",
  "merchant_category": "Electronics",
  "device_type": "Mobile",
  "timestamp": "2026-08-15T12:00:00Z"
}
```

## Limitations

Please note the following boundaries of this prototype:
- **Dataset limitations**: The IEEE-CIS dataset is heavily anonymized. Features like `V1`-`V339` lack business context, limiting the human-readability of some SHAP explanations.
- **Model limitations**: The models are static. They do not currently update their weights dynamically based on new adversarial behavior.
- **False positives/False negatives**: With an XGBoost precision of 22.77%, approximately 3 out of 4 flagged transactions are false positives. This is intentional to maximize recall (catching 70% of all fraud), but requires manual analyst review.
- **Prototype Status**: This is a decision-support prototype. It is designed to assist analysts, not to autonomously block real financial networks without human oversight.

## Future Improvements

- **Streaming transaction integration**: Migrating from REST polling to Apache Kafka / WebSockets for true real-time pub/sub ingestion.
- **Online learning**: Implementing model drift detection and automated re-training pipelines to adapt to new fraud vectors.
- **Graph-based fraud detection**: Utilizing Graph Neural Networks (GNNs) to map behavioral relationships between users, devices, and merchants.
- **Advanced behavioral modeling**: Deep sequential modeling of user clickstreams (mouse velocity, typing cadence) prior to the transaction.
- **Production deployment**: Containerizing the architecture using Docker, orchestrating with Kubernetes, and transitioning from SQLite to PostgreSQL for distributed scaling.
